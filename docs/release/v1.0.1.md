# iqdb-ivf v1.0.1

A fix release. No API changes.

## Fixed

- **A failed `retrain()` keeps the data.** Retrain emptied the inverted
  lists before training, so when training failed (fewer live vectors than
  `n_clusters`, or fewer than the 256 an IVF-PQ codebook needs) every vector
  was gone. It now trains the new model and plans every entry's new cluster
  and code first, and moves nothing until all of that succeeds. On error the
  index is exactly as it was.
- **Hamming probes follow the query.** A centroid is a mean, so under Hamming
  every centroid scored about `dim` and the same clusters were probed for
  every query. Hamming indexes now rank centroids by squared L2, the space
  vectors are assigned in. On random 64-bit codes, recall@10 at 4 of 32
  probes went from 0.11 to 0.48. Other metrics rank centroids as before.
- **NaN distances rank last.** A NaN with its sign bit set used to sort
  before every number under `f32::total_cmp`.
- **Quieter logs.** Duplicate or unknown ids and other caller errors are
  logged at `debug` instead of `error`, and no log event carries the vector
  id.
- **Docs.** IVF-PQ speeds up the scan but keeps the full vectors for the
  rerank, so it does not reduce memory; the README said otherwise. The docs
  also now note that clusters are built in L2, so `DotProduct` and `Cosine`
  on vectors whose norms vary widely have lower recall at a given `n_probes`
  than `Euclidean`; normalize such vectors or raise `n_probes`.

## Security

- **`n_clusters` is capped at `2^20`.** `IvfConfig::validate` and
  `IvfIndex::new` reject larger values with `InvalidConfig`, since the index
  reserves one list per cluster at construction.

## Upgrading

Change the version to `1.0.1`. Hamming IVF indexes return different (better)
results; nothing else changes.
